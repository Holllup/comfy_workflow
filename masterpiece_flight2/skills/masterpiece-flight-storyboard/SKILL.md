# 名画飞行分镜共创

用户提供原画和大致“怎么飞”的想法，Codex 负责把它发展成能被当前工作流消费的完整分镜与提示词。先确认创意，再交付 JSON；不要求用户编写技术字段。运行 ComfyUI、租 GPU 或下载模型需有对应任务授权。

## 确定作品与意图

1. 实际查看完整原画。项目图片可先查 `masterpiece_flight2/pics/sources.json`；仅有标题且版本不明时再问。核对作者、年代、馆藏页面和图像来源，把有据事实与虚构的画外空间分开。
2. 默认采用 FLUX.2 dev＋H3 的 v3：四段电影式梦幻写实飞行，到原画视角停稳，约五秒画作化，一秒定格。横屏中心保留完整原画，AI 延伸的两侧一起画作化。用户明确使用旧油画空间图时才采用 v2。
3. 每轮只问影响设计的 1–3 个问题：从哪里进入、想穿过什么、希望哪种地形遮挡、必须避免什么。已有明确路线就直接深化；没有路线可提 2–3 条针对本画的方案。不要强迫用户填写相机参数或重复选择已确定的风格。

## 把想法整理成可生成的路线

- 先写中文分镜表让用户修改：四镜各约五秒，列出起点、运动、遮挡物、结束画面，以及最后停稳和画作化。只规划能在短段内完成的有限运动，避免瞬间跨村、完整绕山一圈或用传送门掩盖不连续。
- 遮挡来自真实空间里的山肩、岩体、树干、枝叶、墙角等；不要把原画当作屏幕、幕布、背景板或贴纸。遮挡类型字段只是描述，不会自动创建特效。
- 明确 R2/R3/R4 接点的物体左右位置、覆盖比例、到达侧、朝向及运动方向；近中远景应有可辨认视差。R5 对应原画构图，但仍是有真实材质的摄影场景；第四镜末段减速到完全停稳。
- 画作化是独立第五段：机位锁定，材质逐渐成为颜料与笔触，主要地标保持对应，左右延伸同步变化。不能用“飞入画框”或两张透明画面叠化代替这一过程。
- 沿用当前画作自身的建筑、地形与光线。不要把《星月夜》的柏树、教堂和星晕套给其他画。梦幻气氛不等于前段出现油画笔触。

## 输出与工作流对应

确定使用 v3 时读取 [references/story-schema-v3.md](references/story-schema-v3.md)。只有用户明确要求旧 v2 图时读取 [references/story-schema-v2.md](references/story-schema-v2.md)。不要混用两种输入语义。

v3 图像顺序为：原画扩展 A → 写实终点 R5 → R4 → R3 → R2 → R1。R5 的参考图是扩展画作；R4–R1 每步只有下一张写实图作为参考，不再提供原画或抽象色彩种子。视频顺序为四段 R1→R2→R3→R4→R5，再单独 R5→A。

用户确认中文路线后，写出**所有**英文生成提示词：原画扩展、五张关键帧、四段飞行及画作化。用户直接要求最终 JSON 时按该授权交付，不设置必须说某个口令的步骤。源图和路线尚有决定性歧义时先问清。

## 交付与验证

1. 输出单个完整 JSON 对象，默认 `schema_version: 3`、`conditioning_mode: photoreal_to_artwork`。`project_id` 是工作流单独的输入，不塞进分镜协议。中文用于创意说明，英文用于模型动作与画面提示词。
2. 保存至 `masterpiece_flight2/storyboards/<painting_slug>_v3.json`，调用项目 `core.validate_story` 校验；同时人工检查逆向图片与正向飞行是否一致、五个视点是否衔接、画作化是否保持机位。校验器不证明视觉效果。
3. 给文件链接；用户需要直接复制时返回完整 JSON。说明首次在 `01_flux_endpoints.json` 的 `ArtV3Prepare.story_json` 粘贴全部内容，后续阶段按同一项目读取。生成图像的确认与创意确认是两件事，不能把 skill 输出当作已经通过图像审核。
4. 收到生成结果后，先定位是关键帧构图、飞行接点还是画作化出现问题，只改受影响部分并检查连锁影响。重做素材会使对应批准和缓存失效，不承诺仅改提示词能保证三维几何或变形质量。
