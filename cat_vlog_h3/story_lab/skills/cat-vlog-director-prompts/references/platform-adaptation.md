# 平台核对与提示词适配

每期开始、模型或输入模式变化时读取。稳定的导演方法与会变化的平台事实分开维护。

## 本期需要知道的最少事实

| 项目 | 核对内容 | 未确定时怎么继续 |
| --- | --- | --- |
| 图片端 | 用户在 ChatGPT 中使用的生图／编辑方式，本次附图和实际画幅选项 | 可写自然语言图像提示词，不捏造 API 模型名、分辨率或可选参数 |
| 视频端 | 即梦界面实际显示的模型版本、图生视频或其他输入模式 | 继续导演方案，执行时长和输入语法标待核对 |
| 时长 | 当前模式可选的生成长度 | 先给成片节奏意图，再选择真实可用长度并调整动作 |
| 参考 | 本次模式允许哪些图片、视频、音频，数量、角色与标签写法 | 只列实际确认的输入，不声称额外素材已接入 |
| 声音 | 是否支持本次需要的对白、环境声、音乐或音轨参考 | 保留声音意图，区分生成要求与需要后期完成的部分 |
| 其他控制 | 是否有首尾帧、负向栏、延长、种子等本次真正需要的选项 | 不把其他产品或版本的控件搬过来 |

以用户实际界面信息确定其可用选项，再用对应版本的官方资料核实写法。不能用官网介绍推断账户已经开放某功能。一次确认后在本期复用；版本、模式或用户设置改变时才重查。

记录一句可追溯说明即可：版本与模式、核实来源、日期、仍未确定的选项。不建立与当前任务无关的全平台能力表。

## 默认执行方式

图片使用用户参考生成单一静态首帧，用户审图后将该图作为本镜视频输入。每个生成片段保持一个连续镜头，多个镜头由后期剪辑连接。

支持多镜头生成的版本仍不意味着本项目自动改成整段一次生成。用户明确改变方式时，重新设计生成单元和首帧策略；不要让一个首帧暗中承担数个完全不同机位的静态构图。

## 导演稿与执行稿的差别

导演稿可以写“此处使用约两秒的细节镜头”。执行稿必须使用当前平台可选时长，给这个动作留下前后可剪余量，说明成片取用范围。

未确认时长时，不在代码块中塞多个可选数字或占位标签让用户猜。将其标为待核对草稿，或先给不依赖该参数的导演说明；核实后再生成唯一明确的正式版本。

图片参考编号可以用普通说明；视频引用标签只有在所选界面实际支持时才使用。本项目的 R1、F01 等是文档中的素材名称，不是产品通用语法。

## 当前资料的用途

2026-10-14 已阅读的官方图像提示和 Seedance 资料见[研究记录](research-notes.md)。它们提供表达方法与版本核实入口，不构成永久能力配置。特别是 Seedance 2.5 的官方介绍，不能被当作用户当次使用 2.0、mini 或其他版本的参数依据。

不为核对能力创建付费任务或发起生成。用户返回实际首帧、视频或界面信息后，才把其中可观察到的事实作为本项目证据。
